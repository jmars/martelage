why it fails without the fix: MEASURED. The pre-fix verifier has no --ocsp-response option at
        all, so this invocation ends at exit 2 "unknown option --ocsp-response" — the input
        cannot be expressed, and its own docstring says OCSP is "not implemented here at all, not
        even from a supplied OCSP response". With the option added and the status comparison
        removed (the entry is read and never consulted), this container reports exit 0
        CONFORMANT and "checked CLEAN" from root A's CRL, while the response in the same run
        says the sealer is revoked: revocation material the verifier was handed, read and
        ignored. Vector 34 (no revocation input) still reports 0 either way, which is what makes
        this a check and not a tightening
openssl: every call below is run BY THE VERIFIER on the supplied file. Nothing is fetched, no
        request is written and no responder is contacted:

                Next Update: Jan  1 00:00:00 2099 GMT
        The first call is how the response's status, signer, window and each SingleResponse are
        read. The second is the one that decides anything: it verifies the response's own
        signature, requires the signer to be the certificate's issuer or a responder that issuer
        authorised, requires that signer's chain to reach a supplied anchor, and requires the
        response's CertID to be THIS certificate's — a response about another certificate prints
        "ERROR: No Status found." and is never counted for this one
what this vector does NOT claim: that the certificate was revoked at the claimed time, or that no
        responder would say otherwise later. The response is a statement made inside its own
        window (2020-01-01 .. 2099-01-01, fixed in tools/mkocsp.sh so it holds on any host at any
        time); a revocation published after its nextUpdate is invisible here, and the report's
        not-checkable block says so on every armed run
