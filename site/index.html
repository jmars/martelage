Martelage — the Evidence Package standard

Draft 0.2, document identifier martelage 0.2, wire format unchanged at "v":1. A directory format for records, plus one manifest that states the package's scope, its place in a package chain, and whether anyone other than the producer holds its digest.

What an evidence package is

An evidence package is a directory, not an archive (§4.1 MA-16). It holds:

  • Record stream files. JSON Lines files whose records are hash-chained within a stream: each record carries seq, which runs 1..n with no gaps, and prev, the body_sha of the record before it (§6, §7.1–7.2). Two writers' records are never merged into one stream (§6.6).
  • One manifest, package.json, listing every other file in the package with its sha256 and its byte length, and stating three things beyond that file list:
    • the package's scope — what it contains and, separately, what it does not, each absence carrying a meaning word from a fixed vocabulary (§8, MA-54 to MA-60);
    • its place in a package chain — prev.package_sha and prev.how, saying whether a predecessor exists and where that value came from (§7.4);
    • its anchor statement — whether a party other than the producer holds this package's digest, and under which named profile (§9). The slot has named profiles at this version, and one of them is an eIDAS qualified seal — the anchor profiles (§9.3).

The package digest is sha256 over the exact bytes of the manifest. The manifest carries no digest of itself; because it lists every other file's digest, that one value transitively pins every file in the package, including the scope statement and the anchor claim (§7.3.1 MA-47).

All of it is checkable offline, with a POSIX shell and sha256sum, by someone who has never seen the producer: the zero-tooling check on the usage page is a normative property of the format, not an example (§4.6 MA-21).

Why the standard exists: the honest sentence

The threat model comes first, because every mechanism in the standard is derived from it (§3). The adversary is the operator. The party that produced the package is assumed to have administrative control of the machine it was produced on, and can therefore rewrite the system's records, its auxiliary state, the exported files, the manifest and the producing binaries — recomputing every digest inside the package correctly and consistently (§3.1 MA-10). Nothing inside a package proves anything against that party acting coherently; the standard calls this not a defect to be designed away but the residual every mechanism is measured against (§3.2 MA-11).

So the standard states its own residual, and every conforming validator MUST print the following two sentences verbatim on every run that names a package — including a run that reports the package conformant, and including a run that ends at exit code 2 because the package could not be read (§3.3 MA-12):

A package proves that what it contains was not altered after it left; it cannot prove that what it contains is all there was, and against an operator who rewrote everything before the first anchor it proves nothing.

A coherent tamper performed before the first observation is invisible to every mechanism in this standard.

That is the whole position. A format that names its adversary can be argued with; a format that does not cannot (§3). The five mechanisms, and exactly what each buys

Each mechanism is specified and reported separately, because their powers differ by orders of magnitude and a reader will otherwise credit the weakest with the strength of the strongest (§3.4). This is the standard's own table:

The five mechanisms, each with its exact power (§3.4)
# Mechanism What it buys What it does not
i Internal consistency (§5.1–5.2, §6.2, §7.1–7.2) A partial or sloppy rewrite shows as a break: a moved body digest at a fixed position, a gap, a count that disagrees with the payload. A wholesale, internally consistent rewrite passes.
ii Staleness against the previous package (§7.4) Converts an invisible omission into a break visible one package later — if someone kept the earlier package. An operator who starts a fresh chain and was watched by nobody.
iii Witnesses outside the audited subject (§3.6) Forces the operator to rewrite more places consistently. Stops the operator. Each extra rewrite is another place to contradict a copy someone else holds — it multiplies cost, never prevention.
iv The enrollment gap (§3.5) Nothing. It is named so it is not hoped away. —
v The external anchor (§9) Proves a digest existed at a time, held by someone other than the operator. Truth, completeness, or that the operator told the witness everything.

The standard also gives the one-line reading of its own layers, which is the sentence to carry away (§7.6 MA-53):

Layers 0–2 stop tampering with a package you hold; layer 3 bounds tampering across packages a verifier held; only layer 4 binds the package to a party outside the operator's reach.

Two consequences are stated as requirements rather than left to inference. A validator report MUST show which layers were armed, and MUST NOT let an unarmed layer read as a pass (§7, §10.4 item 6). And a chain proves order and integrity over what is present: it does not prove completeness — a consistently-chained prefix, and a consistently-chained subset, pass every check in layers 0 and 1 (§7.2.3 MA-45).

What it is not

  • Not a record format. It does not say what an auditable system should record, in what schema, or with what semantics. It defines the outer layer that carries someone else's records; the record grammar is the payload's own business, named and not specified here (§0.5 MA-5).
  • Not a claim about the records. A conformant package may contain records that are false, and may omit records that existed. Conformance says the package is well-formed and self-consistent; it says nothing about truth or completeness (§2.2 MA-7).
  • Not a certification, and not a registry. No registration, no permission and no fee is required. A third party claims conformance by publishing a statement in its own name, naming the requirements it relies on and any it does not satisfy, with the reason; the standard certifies no one (§2.4 MA-9).
  • Not a service. The reference validator runs offline with a POSIX shell and the utilities §10.1 names: no network, no interpreter beyond those, no key material, no service, no producer (§10.1 MA-68).
  • No keys, and no third party required for the base tier. A package with no third party, no seal, no timestamp and no key material is fully conformant; nothing in the conformance definition requires any of them (§9.1(a) and (b), MA-61). The anchor is an optional slot, not a tier.
  • Not a ladder. There is one level, deliberately: a ladder reads as "the lower tier is deficient", which is backwards, since the unanchored tier is the adoption surface (§2.3 MA-8).
  • Not a promise about the producer. A validator is not required to know a producer; producer is a claim under the producer's own name (§10.8 MA-75).

One implementation is named in the standard's Annex A, and only there. That annex is informative: nothing in it is required to conform, and removing it would leave the standard whole.

The name

Martelage is the forestry marking of trees with a hammer, by a party other than the owner: a durable mark, attributable to whoever struck it, that decides which trees are retained. The standard's own text does not gloss its name anywhere (MEASURED: no occurrence of "forestry" in spec/MARTELAGE-0.1.md or README.md); the sentence above is the name's plain sense, an INTERPRETATION, and no clause of the standard depends on it.

Status

  • Draft 0.2 — published for adoption and criticism; not yet a stable standard. A change to this document's requirements may be breaking while it is a draft; a change to the published wire format ("standard":"martelage","v":1) must not be (§11.6 MA-81). The bump from the first draft to this one is recorded in §11.7 (MA-83): the verifier surface grew and the wire format did not, so a package written for the first draft is a 0.2 package.
  • Every normative requirement carries an identifier, MA-1 … MA-83, so a conformance report can cite what it reports as met or unmet; a clause that cannot be cited cannot be tested (§0.3 MA-3). MEASURED: all 83 identifiers appear in the specification.

  • Where it lives: the specification is spec/MARTELAGE-0.1.md; the reference validator is validator/martelage-verify and validator/p3-verify; the fifty-eight test vectors are under vectors/, each with an expected.txt.
